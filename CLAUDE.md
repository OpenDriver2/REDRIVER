# OpenDriver1 / Driver — rebuilding the source from IDA

Reply in the user's language. This file and `docs/` are kept in English.

Goal: translate the decompiled Driver (PC) code from the IDA database into `.c` source files under
`src_rebuild/game6.4g/`. That tree already holds empty placeholder files laid out like the original
source; the job is to fill them in. The long-term plan (finish the decompilation, then port to SDL
and OpenGL) is in [docs/PLAN.md](docs/PLAN.md).

## Before editing

1. Read this file completely, and the docs below that the task needs (for translation work:
   `architecture.md`, `ida.md`, `translating.md`, `building.md`; `references.md` when a reference
   may help).
2. Run `git status --short`. The worktree is shared and often dirty; assume every existing change
   belongs to the user or another agent.
3. Read [docs/COMMIT_MESSAGES.md](docs/COMMIT_MESSAGES.md) before committing, and
   [docs/PLAN.md](docs/PLAN.md) when the task touches what comes next (platform code, porting).
4. Check whether another agent is working on the same files. Partition the work (by source file
   or IDA folder) or coordinate before editing overlapping code. `src_rebuild/stubs/stubs.c` is
   regenerated by every build of `tools/build.sh`, so two agents translating at once must not both
   regenerate and commit it; the IDA database is shared too (one `ida-mcp` session, never modified).
5. At the start of each new task in a long-running session, and always right before committing,
   check whether this file or the docs you rely on changed since you read them
   (`git status --short -- CLAUDE.md docs/`, `git log -1 --format=%h -- CLAUDE.md docs/`).
   Re-read any that changed and follow the current version; other agents may update the rules
   in parallel sessions.

## Key rules

- Do **not save or modify** the IDA database (renames, types) unless the user asks.
- The translation is written from IDA; references are for orientation only — never copy
  reference functions. Never modify the reference repositories.
- Every function carries its address and status (`// [0xADDR] [D]`); intentional behaviour
  changes are `[A]` with a `// NOTE:` saying what and why. The agent sets only `[D]` and `[A]`.
- Mark guesses with `// NOTE:` and mention them in the reply.
- Build after translating and fix errors before reporting; when running the game, back up
  `data\debug.log` first.

## Commits

- Commit only when the user asks. Write commit messages following
  [docs/COMMIT_MESSAGES.md](docs/COMMIT_MESSAGES.md).
- Before running `git commit`, prepare the commit following "Review before committing" in
  `docs/COMMIT_MESSAGES.md` (check the index, stage only the task files or use
  `git commit --only` when others have staged files), show the user the file list and the full
  commit message, and commit only after the user confirms.

Example of a finished file: `src_rebuild/game6.4g/frontend/cars.c`; with data-ownership analysis:
`src_rebuild/game6.4g/shell.c`.
